## Standing rules (do not break)

- **Never push anything to GitHub** (no `git push`, no PRs) unless the user explicitly asks. Don't commit unless asked. Remote is `NexzoraLabs/elmonx-app`.
- **Never touch production identifiers.** iOS and Android both use `com.elmonx.app.dev` for now. The old live Unity app is `vizz.VtailApp` (iOS) / `com.app.elmonx` (Android); the bundle ID switch happens only once all features are built — don't change it without the user asking.
- **Never run `expo prebuild` / `--clean`.** `ios/` is hand-maintained with the Unity integration and would be wiped. For new native deps run `cd ios && pod install`, then rebuild in Xcode.
- **Use the same APIs as the website.** Before building a screen, read the website component + `api.ts`, then confirm fields against the backend validator/controller.
- **No fake functionality.** If the backend doesn't support something the design shows, tell the user and ask (AskUserQuestion) rather than faking it or storing it locally.
- Design screenshots are mockups: they sometimes contain copy-paste errors (wrong labels like "Price" for phone, "Delete Post", placeholder text from other screens, typos like "Cacel"). Fix those silently-obvious ones and mention them.
- Testing is on a **real iPhone via cable** (Unity doesn't build for the simulator — IL2CPP baselib gap). The user builds/installs from Xcode.

## Definition of done for EVERY UI change (do it unasked — the user won't repeat it)

1. **Translations:** every new/changed user-facing string goes through `t()` / `i18n.t()` AND gets its translation added to **all** `src/i18n/locales/*.json` (ja, es, fr, zh-Hant, zh-Hans, ko — whatever exists) in the same change. Then `npm run i18n:check` must print ✓ for every language. New label lists rendered via `t(variable)` → add the constant to `EXTRA_CONSTANTS` in `scripts/i18n-check.js`.
2. **Motion:** new buttons, cards, lists, tabs and toggles use the motion system (below) — never a bare `Pressable` for a button/card, never ad-hoc durations/springs.
3. `npx tsc --noEmit`, `npx eslint src`, bundle check (see bottom of Architecture).

## Architecture and conventions

- Routes: `src/app/(auth)/*` (login flow), `src/app/(tabs)/_layout.tsx` is a Stack holding the drawer + home tabs and all pushed screens. Register every new pushed screen there with `animation: 'slide_from_right'`.
- API clients live in `src/services/*-api.ts`, base URL `https://api.elmonx.com/api`, auth via `Authorization: Bearer <token>`.
  - **Always go through `services/http.ts`** (2026-10-23 audit): `apiFetch` (20 s timeout, 90 s for FormData uploads, readable "no internet"/"timed out" errors — RN fetch has no timeout), `readJson` (a Cloudflare/nginx HTML error page becomes "server not responding", not a JSON parse crash), `getJson`, `assertSuccess(envelope, { rejectStatus201 })` (posts/feed/chat/profile routes use body `status: 201` for business errors). Never call bare `fetch` + `response.json()` in a service.
  - **Paginated lists append with `appendUnique(prev, page, keyOf)`** (`services/http.ts`) — offset paging repeats rows when data changes between pages (duplicate rows + duplicate React keys). Guard load-more with a ref, not state (FlatList can fire `onEndReached` twice before the re-render). Long lists are `FlatList`, never `ScrollView` + `map`.
  - Website links: `SHARE_URL` (`config/env.ts`, always `https://elmonx.com`) for share links, legal pages, articles; `WEB_URL` only for the env's own website (app-login hand-off, Buy on Web). Website path → app route: `services/website-links.ts` (`mapSegments`, `appRouteForWebsiteUrl`), shared by `+native-intent` and Home banners.
  - **Multipart uploads: always `appendLocalFile(form, field, uri)` (`services/upload-file.ts`).** Expo 57 swaps global `fetch` for `expo/fetch`, which rejects RN's `{ uri, name, type }` part ("Unsupported FormDataPart implementation"); an expo-file-system `File` works (filename + mimetype come from the file).
  - Don't open a RN `Modal` from a modal screen, and don't use KeyboardAvoidingView inside an iOS page sheet — `create-post` is `fullScreenModal` for that reason and its GIF picker is an in-screen overlay.
  - **The backend returns HTTP 200 even for logical failures.** Every client has an `assertSuccess` that checks `success === false` or body `status >= 400`. Keep this pattern.
- Auth: `src/context/auth-context.tsx` — `useAuth()` gives `user`, `token`, `signIn`, `confirmSignInOtp`, `signOut`, `updateUser(partial)` etc. Token/user persisted in `expo-secure-store`.
- **Theming (dark + light, 2026-10-22):** colors only from the active palette — `src/constants/app-colors.ts` has `DarkColors`/`LightColors` (same keys; `LightColors` mirrors the website's light theme), but **never import a palette into a component**. Inside components: `const AppColors = useAppColors();` for inline colors and `const useStyles = makeStyles((AppColors) => ({...}))` + `const styles = useStyles();` instead of a module-level `StyleSheet.create` that uses colors (both from `@/context/theme-context`). Module-level constants that need colors store palette **keys** (`AppColor`) and resolve them in the component (see `rarity-badge.tsx`). Text/icons on photos or dark scrims use `AppColors.onMedia` (white in both themes), scrims `mediaScrim`, faint fills `subtleFill`, and the very faint well behind artwork on NFT cards `imageWell` (4% white dark / 3.5% black light — used by `CollectionGridCard`, `NftGridCard`, `CollectibleCard`; use it for any new card image area). Card image layout (VeVe-style): the well runs edge to edge across the top of the card with no margin and no radius of its own (the card's `overflow: hidden` + radius rounds the top corners, bottom stays square); the artwork sits inside with `artInset` (12px) and `contentFit="contain"`. Badges go over the artwork's bottom-left via `components/collections/card-image-badges.tsx` (`CardImageBadges`, website nft-card rules; 18pt tall): edition tags are design images in `assets/images/badges/` with text baked in (`ArtistProofTag`, `StudyTag`; `DigitalProofTag` was generated from the Artist Proof tag in blue — replace when design sends theirs, update its aspect), blind box `rarity` = blank design pills (`RegularLabel`/`RareLabel`/`SecretRareLabel`/`LegendaryLabel`, 480×108) with the translated label drawn on top — hidden for SPECIAL_DROP_IDS — and an "Airdrop" scrim pill when `priceKind === 'airdrop'`; card bodies show only the date-time (no Dropped/Dropping label). Used by `CollectionGridCard` and the Home `CollectibleCard`. `ThemeProvider` (root `_layout.tsx`) persists the choice in SecureStore (`elmonx_pref_dark_mode`, read synchronously at launch), calls `Appearance.setColorScheme` so native alerts/keyboard follow it, and drives the navigation theme, status bar and the AppKit modal. Toggle: sun/moon icon in `home-header.tsx` + Settings → Dark Mode (`useTheme()`). The splash follows the phone's appearance natively and cross-fades to the app theme (see App icon + splash).
- **Translations (7 languages, 2026-10-23):** English, 日本語 `ja`, Español `es`, Français `fr`, 繁體中文 `zh-Hant`, 简体中文 `zh-Hans`, 한국어 `ko` — `LANGUAGES` in `src/i18n/index.ts` (order = Language screen order; each has a `locale` for date formats). i18next + react-i18next + expo-localization, imported first in root `_layout.tsx`. **Keys are the English strings**: `t('Create Account')`; English has no resource file, anything missing falls back to English. Translations live in `src/i18n/locales/<code>.json` (brand names/units like XP, ElmonX, GIF are left out and fall back). Device language on first launch: Chinese with script `Hant` or region TW/HK/MO → `zh-Hant`, other Chinese → `zh-Hans`. Rules for every new string the user can see:
  - In components/hooks: `const { t } = useTranslation();` → `t('Text')`, variables via `t('Bid of {{amount}} X-coins placed.', { amount })` — never glue sentences from pieces or template literals (word order differs in French). Outside React (services, module helpers, error messages) use `i18n.t(...)` from `@/i18n`. Inside fetch `useCallback`/`useEffect` bodies use `i18n.t` too, so `t` doesn't become a dependency (it would refetch on language change).
  - Module-level lists/maps (tabs, menu rows, statuses, `data/*.ts`) keep English and are translated where rendered: `{t(row.label)}`. Values sent to the backend stay English (gender, report reasons, filter values).
  - Same English word, different French meaning → i18next context: `t('Following', { context: 'button' })` (key `Following_button`).
  - Dates: `toLocaleDateString(appLocale('en-GB'), …)` (French users get fr-FR); 12h clock only for English (`currentLanguage() === 'en'`).
  - Backend content (drop/collection titles, descriptions, backend error messages, rank names Viewing…Canon) stays as sent.
  - After adding strings, add the translation to **every** `locales/*.json` (same `{{placeholders}}`) and run `npm run i18n:check` (`scripts/i18n-check.js`: missing / placeholder-mismatch / `--unused` per language, exit 1 on missing). Simplified Chinese was produced from Traditional with OpenCC `tw2sp` plus mainland terms (关注, 拉黑, 帖子, 账户, 邮箱, 点赞) — keep that vocabulary.
  - Language screen: My Account → Language (`(tabs)/language.tsx`, `setAppLanguage`, saved in SecureStore `elmonx_pref_language`; first launch uses the phone language if supported).
  - iOS permission prompts: `ios/elmonxapp/<code>.lproj/InfoPlist.strings` for all 6 non-English languages (children of the `InfoPlist.strings` variant group in the Xcode project, all in `knownRegions` and `CFBundleLocalizations`; mirrored in `app.json` `locales` → `src/i18n/native/<code>.json`). A new language needs a new lproj + project entry (runtimeVersion bump). These follow the iPhone's language setting (iOS Settings → ElmonX → Language), not the in-app choice — iOS limitation. Same for the native share sheet / image picker and the Reown wallet modal.
- **Motion system (2026-10-23)** — one consistent feel, so NFT-app polish shows up everywhere automatically. Tokens only from `src/constants/motion.ts` (`MOTION.duration/easing/spring/pressScale/stagger`); primitives from `@/components/motion`:
  - `PressableScale` — drop-in `Pressable` that squishes while held. `pressScale="button"` (0.96) for buttons/pills/icon buttons, `"card"` (0.98) for tiles; `haptic="light"` on primary buttons. Already inside `AuthButton`, `RewardPillButton`, `ViewIn3DButton`, `CollectionGridCard`, `CollectibleCard`, `AuctionCardHome`. Never put an `entering` animation on it (both are transforms and clash) — put the entrance on a wrapper `Animated.View` that also carries the card's width (see `CollectionGridCard`). Don't use it for full-width list rows or backdrops (keep their opacity feedback).
  - `Appear` / `enterAt(index)` — standard list/grid entrance (rise 14px + fade, 45ms stagger over the first 10 items, later items just fade). Wrap each `renderItem` in `<Appear index={index}>`; if the card's width is a % of its parent, move that width onto the `Animated.View entering={enterAt(index)}` wrapper. In use: collections/collectibles/auctions grids, artists, feed posts, notifications, auctions list.
  - `TabIndicator` — tab underline that grows/shrinks on change (`<TabIndicator active={…} style={[styles.underline, styles.underlineActive]} />`); used by `CategoryTabs`, `SegmentTabs`, collectibles/connections/profile tabs. Tab presses fire `haptic('selection')`.
  - `PopIcon` — bounce when an icon turns on (like hearts in feed + drop page). Pair the press with `haptic('light')`.
  - `haptic(kind)` (`expo-haptics`): `light` taps, `selection` tab/pill/toggle changes, `medium` follow-type actions, `success`/`error` results (reward claim banner, X-Coin purchase, bid placed).
  - Bottom sheets slide up (`BottomSheet`), screens use `slide_from_right`, skeletons pulse (`Skeleton`). Everything respects iOS Reduce Motion (`MOTION.reduceMotion`, `useReducedMotion`).
- Screen template: `SafeAreaView` + header row (36px round back button, centered title, right spacer/action) — copy from an existing screen like `settings.tsx`.
- Reusable bits: `components/ui/bottom-sheet.tsx` (sheet with grabber, used for forms/confirms), `components/auth/auth-button.tsx` (big 56px pill button — not for small inline buttons), `components/account/user-avatar.tsx` (real avatar via `profile_avatar_url || profile_avatar`, placeholder fallback), `components/rewards/reward-pill-button.tsx` (small status pill).
- Drop / collection cards navigate through `openGridItem(item)` (`components/collections/open-grid-item.ts`) — individual blind box items have their own page.
- Ticking countdown text uses `useNow()` (`hooks/use-now.ts`, one shared 1 s clock) inside the small component that shows it — never a `setInterval` that re-renders a whole screen/list. Auction timers: `components/auction/auction-time-left.tsx`, `auction-countdown.tsx`.
- Sentences with a styled/tappable word use `rich(t('… {{name}} …', slots('name')), { name: <Text …/> })` (`i18n/rich.tsx`) — one key per sentence. Plurals: separate keys picked in code (e.g. `followersLabel(count)` in `i18n/index.ts`).
- Auth guard: root `_layout.tsx` uses `Stack.Protected` — `(tabs)` only when signed in, `(auth)` only when signed out (both while the session is loading). Sign-out (`auth-context` `clearAccountState`) also disconnects the AppKit wallet and clears the ownership / user-id / unread caches and the query cache.
- Unread notification badge = `hooks/use-unread-notifications.ts` (shared store, refreshed on app foreground, bumped by the `notification:new` socket event, zeroed when Notifications loads). Chat state is keyed per account (`ChatProvider` → `ChatSession key={user_name}`); presence/typing live in `useChatPresence()`.
- Lint is strict (React Compiler rules, `npx eslint`): no `Date.now()` during render (use `useState(() => Date.now())`), no `setState` in effects. Fetch-on-mount effects use `// eslint-disable-next-line react-hooks/set-state-in-effect -- initial data fetch on mount`. To reset a form on open, remount it with a changing `key` instead of an effect.
- Verify every change with: `npx tsc --noEmit`, `npx eslint <files>`, `npm test` (jest-expo unit tests in `src/__tests__/`, import `describe/it/expect` from `@jest/globals`; never put tests under `src/app/` — those are routes), and a Metro bundle check (`npx expo start --port 8099` then `curl "http://localhost:8099/node_modules/expo-router/entry.bundle?platform=ios&dev=true"` → expect HTTP 200). For native changes also `xcodebuild -workspace ios/elmonxapp.xcworkspace -scheme elmonxapp -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build`.
